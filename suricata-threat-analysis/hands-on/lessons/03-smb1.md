# SMB1マーカーを探す：WannaCryとの違い

**学習分類：安全な模擬PCAP／解答付き。実際のマルウェア通信ではありません。**

## 問題

`hands-on/pcaps/03-smb1-marker.pcap`をWiresharkで開き、検出条件に一致する通信元・宛先・対象バイトを特定してください。次に対応するSIDを調べ、アラートだけから侵害と判定できるか考えます。

## 操作手順

1. 表示フィルタに ``tcp.port == 445`` を入力。
2. `Ctrl+F`（Macなら `Cmd+F`）→ `Hexadecimal Value` または `String` → `Packet bytes` にて `ff:53:4d:42` を検索。
3. 関連TCP通信は右クリック → `Follow → TCP Stream` で復元。（DNSの場合はパケット詳細のQueriesを展開。）
4. `frame.number == 4` を表示フィルタへ入力し、下の答えと照合。
5. 次でSuricataのローカル演習ルールをテスト（プロジェクト直下で実行）。

```bash
mkdir -p logs/03
sudo suricata -c /etc/suricata/suricata.yaml \
  -S "$PWD/rules/lab.rules" \
  -r "$PWD/hands-on/pcaps/03-smb1-marker.pcap" \
  -l "$PWD/logs/03"

jq 'select(.event_type=="alert" and .alert.signature_id==9900003)' logs/03/eve.json
```

## 解答（事前に確認できるPCAP事実）

| 項目 | 正解 |
|---|---|
| 送信元IP | `192.0.2.31` |
| 宛先IP | `198.51.100.44` |
| 通信ポート | `51531 → 445` |
| 該当フレーム | **4** |
| 演習ルールのSID | `9900003`（ローカルルール・ETのSIDではない） |
| 実際のデータ | NetBIOS風ヘッダーに続くSMB1識別バイト `ff 53 4d 42` |
| 意味 | 実際のSMBコマンドとして完全な構造ではなく、EternalBlue攻撃ではない。SMB1ヘッダーはWannaCry固有のIOCではない。 |

**深掘り：** WannaCryの感染拡大はMS17-010に関連するが、単にSMB1が見えただけでは脆弱性悪用の証拠ではない。

## 正解の扱い方

上のフレーム番号とバイト列は本リポジトリの生成コードとPCAPから検証したものです。`suricata`エンジンの出力そのものを制作環境で実行したわけではないため、**アラートの件数・フレーム番号は機械実測として断言していません**。使用者側で `suricata -T` とPCAP解析を実行し、実際の`eve.json`と照合してください。
