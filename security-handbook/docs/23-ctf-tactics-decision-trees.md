# 23｜CTF高難度対応：推論・時間配分・エラー診断の判断木

> 「上位に必ず入れる」万能構文は存在しない。再現性のある観測、仮説の優先順位、時間管理、見落とし防止が強みになる。

## 1. 競技開始直後の10分：盤面を作る

```text
0-2分   主催者の許可範囲／ルール／スコア／対象URLを確認
2-4分   HTTP基準 GET /, 存在するpath, 存在しないpath
4-6分   ページのフォーム、リンク、JS、Cookie、認証状態を記録
6-8分   パラメータ単位で入力を変え、観測差をノートに残す
8-10分  SQLi/XSS/OSコマンド/認可/パス探索などの仮説を順位付け
```

テクニックを10個同時に試しても「なぜできたか」が分からなくなる。まず攻撃面を整理する。

## 2. 現象別の判断木

```text
HTTP 405 → Methodとpathを最初に確認 → ブラウザの本来の通信は?
HTTP 500 → 入力のバリデーション? SQL例外? テンプレート例外? バックエンドログ?
HTTP 200 → 画面と生本文が一致する? JS描画か?
真/偽で差 → 本文差? 件数差? 時間差? SQLエラーとの区別?
入力反射 → HTML本文? 属性? JS? URL? DOM sink?
パス403 → 本当にそのルートのアクセス制御? 一律403?
OSシェル No output → stdout/stderr/終了コード/実行コンテキストを区別
```

## 3. 実験ノートは「仮説→反証」を書く

| 項目 | 例 |
|---|---|
| 仮説 | `name`がSQL文字列リテラルへ連結される |
| 対照 | 正常名・絶対にない名・異常引用符 |
| 期待 | 引用符で処理が変わる、SQL例外と不一致の応答は別 |
| 観測 | 500と0件が異なる |
| 結論 | SQL入力処理に問題の疑い。実害は未確定 |
| 反証 | パラメータ化へ変更すると再現しなくなるか |

## 4. 競技中の時間配分（例）

| 割合 | 注力すること |
|---|---|
| 20% | 盤面と入力箇所の把握 |
| 40% | 上位仮説の手動実験と再現 |
| 20% | 回答条件とログ・ファイルの整理 |
| 20% | 未解決問題を再検討し、単純な見落としを解消 |

難しさだけで高得点とは限らない。**確実に解ける問題**と**理解に時間がかかる問題**を分ける。多数のパラメータにペイロードを乱射するより、**反射文脈と処理系を同定してから最小手数で試す**。

## 5. 12の典型的な勘違い

1. 200なら目的のページがある → soft404がある。
2. 403ならファイルが存在する → 一律403の可能性。
3. 500ならSQLiがある → 多様な例外。
4. `OR 1=2`は必ず偽 → 元の条件が真なら真になり得る。
5. `:name1`はPHP変数 → 名前付きプレースホルダー。
6. `prepare()`の文字列に外部入力を連結しても安全 → 連結箇所は未保護。
7. `<b>`が太字ならXSS成立 → HTMLインジェクションの証拠に留まる。
8. `innerHTML`の`<script>`は必ず実行 → DOM挿入時は一般にそうならない。
9. JSから3番目の`p`は `[3]` → `[2]`。
10. `secure_file_priv=''`なら任意ファイルが読める → FILE権限・OS権限・存在確認が必要。
11. `os-shell>`に入ったらSSHと同じ → SQLmapの中継方式・出力回収の制約。
12. `find /`に結果なしならファイル不存在 → 権限・異なる名前空間・エラー隠蔽。

## 6. 評価基準：正答より「再現できる理解」

CTFの記録には **(a)入力位置、(b)元の処理、(c)HTTPの変化、(d)原因の文法、(e)必要な権限、(f)根本対策、(g)修正後の再検証** の7点を残す。仲間に数分で引き継げる記録は強い。

## 7. ラボ演習の進捗表

- [ ] A: GET/POSTの違いをcurlだけで説明できる
- [ ] B: SQL真/偽ペアを再現して偽陽性を排除できる
- [ ] C: XSSのHTML本文と属性値の違いを説明できる
- [ ] D: DOMの3番目のp要素をJSから変更できる
- [ ] E: `exec()`と`dns_get_record()`の権限境界を説明できる
- [ ] F: 「ファイルを発見」「読める」「実行できる」を区別できる
- [ ] G: DIRB系の小規模パス探索をcurlで再現できる
- [ ] H: 総括でSQLi/XSS/OSコマンドの各修正点を説明できる
